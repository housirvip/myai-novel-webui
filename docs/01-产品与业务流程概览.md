# 产品与业务流程概览

## 1. 系统定位

`myai-novel-webui` 是一个用于 AI 小说创作流程管理的前端控制台。它不是单纯的内容展示页，而是一个围绕作品生产过程构建的操作界面，核心目标是把书籍管理、章节推进、资源整理、成稿阅读以及个人运行参数配置整合到同一套 WebUI 中。

从前端视角看，这个系统承担的是“可视化工作台”的角色：

- 帮助用户进入某一本书的上下文。
- 帮助用户按章节推进创作流程。
- 帮助用户维护世界观、角色、势力、物品、伏笔等结构化资源。
- 帮助用户阅读最终成稿，而不是混杂草稿和中间态。
- 帮助用户为工作流配置默认的 LLM Provider / Model / Tokens 参数。

## 2. 核心对象

### 2.1 书籍

书籍是整个系统的一级上下文。用户通常先进入书籍总览，再选择一本书进入后续工作区。一本书承载：

- 作品标题与简介
- 目标章节数
- 当前创作状态
- 属于这本书的章节、资源和阅读视图

### 2.2 章节

章节是创作流程的最小工作单元。系统围绕章节提供：

- 基础元信息维护
- 阶段内容查看与编辑
- 工作流任务执行
- 审阅与定稿推进
- 成稿阅读入口

### 2.3 资源

资源是辅助创作的结构化知识库，主要用于让章节工作流获得更明确、更可复用的上下文。当前系统中资源类型包括：

- Outlines
- World Settings
- Characters
- Factions
- Relations
- Items
- Hooks

### 2.4 成稿阅读

阅读页只面向最终成稿（final）内容，不会自动回退到草稿。这保证了“创作中内容”和“可阅读内容”之间的边界清晰。

### 2.5 个人运行配置

个人设置页用于配置当前用户的默认运行参数，例如 Provider、模型、Max Tokens、Provider 连接参数等。这些配置会作为章节工作流的默认值来源。

## 3. 核心业务流程

## 3.1 登录或注册

用户通过登录页或注册页进入系统。登录后，系统会恢复当前会话，并将未登录用户拦截在受保护页面之外。

## 3.2 进入书籍总览

登录成功后，用户会进入书籍总览页。这里可以：

- 查看已有书籍
- 快速创建新书籍
- 进入某一本书的专属工作空间

这一步决定了后续页面的书籍上下文。

## 3.3 进入书籍工作台

进入书籍后，用户会到达书籍工作台。这里通常是一本书的总控页，用于：

- 修改书籍信息
- 查看章节列表
- 创建新章节
- 编辑章节基本信息
- 选择章节后进入章节工作台
- 跳转到资源中心和阅读页

它是“书籍级管理”与“章节级创作”之间的桥梁。

## 3.4 在章节工作台推进章节流程

章节工作台是系统的核心页面。围绕单一章节，用户可以：

- 查看当前 workflow 状态
- 在 plan / draft / review / final 等阶段之间切换
- 启动计划、草稿、审阅、修订、批准等任务
- 查看任务状态、执行结果与阶段内容
- 调整本次运行所用的 provider / model
- 选择或编辑与章节相关的资源引用

从业务理解上，这一页就是章节生产线。

## 3.5 在资源中心维护创作资料

资源中心负责维护这本书的长期知识库。用户可以在这里创建、修改、删除各种资源记录，帮助后续章节 workflow 获取稳定上下文。

这些资源既是独立的结构化资料，也会影响章节工作台中的生成输入。

## 3.6 在阅读页查看最终成稿

当章节已经形成 final 成稿后，用户可以进入阅读页进行顺序阅读。阅读页支持：

- 在章节之间切换
- 调整字号
- 切换版心宽度
- 切换亮色 / 暗色模式

如果某一章还没有 final，阅读页会明确提示需要回到章节工作台完成定稿。

## 3.7 在个人设置中维护默认参数

用户可在个人设置页保存默认运行配置。它的意义在于：

- 为章节 workflow 提供默认 provider / model 组合
- 统一当前用户的运行偏好
- 允许在单次 workflow 请求中进行临时覆盖，但不改变长期默认值

## 4. 页面之间的协作关系

从业务上看，这几个主要页面形成如下关系：

1. 登录 / 注册：解决用户进入系统的问题。
2. 书籍总览：解决“我现在要进入哪本书”的问题。
3. 书籍工作台：解决“这本书当前有哪些章节、该进入哪里继续工作”的问题。
4. 章节工作台：解决“如何推进这一章的生产流程”的问题。
5. 资源中心：解决“世界观与素材如何长期维护和复用”的问题。
6. 阅读页：解决“如何只阅读最终成稿”的问题。
7. 个人设置：解决“工作流默认参数来自哪里”的问题。

## 5. 给新读者的建议

如果你第一次接触这个系统，建议先用下面的顺序理解它：

1. 把它当作“AI 小说工作台”来看，而不是通用 CMS。
2. 先理解书籍、章节、资源、成稿四个核心对象。
3. 再理解页面之间的流转：书籍总览 → 书籍工作台 → 章节工作台 / 资源中心 / 阅读页。
4. 最后再关注个人设置如何为 workflow 提供默认参数。

这样更容易建立完整心智模型。
