# 路由与权限说明

这份文档说明当前前端的路由组织方式、路径约定、鉴权逻辑和页面访问边界，方便后续维护者在新增页面或调整登录流程时快速定位影响范围。

## 1. 路由入口

应用路由集中定义在：

- `src/app/router.tsx`

路由使用 `createBrowserRouter` 组织，最外层统一挂载 `AppShell`，页面作为它的子路由渲染。

## 2. 当前主要路由

当前主路由包括：

- `/`：重定向到 `/app`
- `/app/login`：登录页
- `/app/register`：注册页
- `/app`：书籍总览
- `/app/books/:bookId`：书籍工作台
- `/app/books/:bookId/chapters/:chapterNo`：章节工作台
- `/app/books/:bookId/read`：章节阅读页
- `/app/books/:bookId/resources`：资源中心
- `/app/settings`：个人设置
- `*`：404 页面

## 3. 路由层级关系

可以把路由理解为两层：

### 3.1 应用外壳层

`AppShell` 是外层布局组件，负责：

- 侧边导航
- 顶部标题与当前用户信息
- 当前书籍上下文提示
- 页面主体容器

登录页和注册页虽然也在同一个路由树里，但 `AppShell` 会识别它们属于认证页面，并直接渲染子路由内容，不套用常规应用框架。

### 3.2 页面内容层

所有具体页面都作为 `AppShell` 的子内容渲染。这样可以保证：

- 非认证页拥有统一导航与外观
- 页面切换时保留一致的框架体验

## 4. 路径约定

路径工具集中定义在：

- `src/lib/routes.ts`

目前提供了以下常用函数：

- `bookDashboardPath(bookId)`
- `bookReaderPath(bookId)`
- `bookResourcesPath(bookId)`
- `chapterWorkbenchPath(bookId, chapterNo)`
- `settingsPath()`
- `parseBookId(value)`
- `parseChapterNo(value)`

建议在代码里优先复用这些工具，而不是在页面中手写路径字符串。这样更容易统一调整。

## 5. `/app/` 基路径约定

Vite 配置中设置了：

- `base: "/app/"`

这意味着应用部署和资源解析都围绕 `/app/` 作为前端基路径。开发服务器还额外处理了：

- 访问 `/app` 时，重定向到 `/app/`

因此：

- 在文档和联调中，优先使用 `/app/` 相关路径理解前端入口。
- 路由设计时应默认应用运行在这个前缀下。

## 6. 登录态与会话恢复

鉴权上下文定义在：

- `src/app/auth.tsx`

它承担的职责包括：

- 读取当前 session
- 暴露 `login`
- 暴露 `register`
- 暴露 `logout`
- 暴露 `refresh`
- 提供 `isAuthenticated` 与 `isLoading`

会话状态本质上通过 React Query 管理，session 数据挂在：

- `queryKeys.authSession()`

这说明登录态不是一个孤立的本地布尔值，而是应用级服务端状态的一部分。

## 7. 页面访问守卫

路由守卫定义在：

- `src/app/route-guards.tsx`

当前主要有两类守卫。

### 7.1 `ProtectedRoute`

用于保护必须登录后才能访问的页面，例如：

- 书籍总览
- 书籍工作台
- 章节工作台
- 资源中心
- 阅读页
- 个人设置页

它的行为是：

- 如果 session 还在恢复中，显示“正在恢复会话”提示。
- 如果用户未登录，跳转到 `/app/login`。
- 如果用户已登录，继续渲染页面。

另外，未登录跳转时会保留来源路径，便于登录后返回目标页面。

### 7.2 `AuthOnlyRoute`

用于限制“仅未登录用户可访问”的页面，例如：

- 登录页
- 注册页

它的行为是：

- 如果 session 正在恢复，显示加载提示。
- 如果用户已经登录，直接跳转到 `/app`。
- 如果用户未登录，允许访问当前页面。

## 8. `AppShell` 中的书籍上下文导航

`AppShell` 会根据当前路由参数中的 `bookId` 判断是否已经进入某本书的上下文。

这会直接影响侧边栏导航：

- 书籍总览：始终可访问
- 写作工作台：需要当前书籍上下文
- 资源中心：需要当前书籍上下文
- 章节阅读：需要当前书籍上下文
- 个人设置：始终可访问

如果当前不在任何书籍上下文中：

- 相关入口会被禁用或回退
- 页面会提示先从书籍总览进入一本书

这使得导航和当前业务上下文保持一致。

## 9. 新增页面时需要考虑什么

如果你要新增一个页面，至少要同步考虑下面几项：

1. 是否需要在 `src/app/router.tsx` 注册路由。
2. 是否需要受 `ProtectedRoute` 保护。
3. 是否应该只允许未登录用户访问。
4. 是否需要在 `src/lib/routes.ts` 增加路径构造函数。
5. 是否需要出现在 `AppShell` 导航中。
6. 是否依赖当前书籍上下文。
7. 是否需要支持从登录后自动回跳。

## 10. 调整登录流程时需要关注什么

如果你修改登录、注册、登出或会话恢复，通常要同时检查：

- `src/app/auth.tsx`
- `src/app/route-guards.tsx`
- `src/app/router.tsx`
- `src/app/layouts/AppShell.tsx`
- `src/lib/query/query-client.ts`

尤其要注意 401 未授权和 session 失效后的页面行为是否仍然一致。

## 11. 理解这套路由的一个简化心智模型

可以把当前前端路由理解成：

- 登录前：只允许访问登录 / 注册。
- 登录后：从 `/app` 进入业务主界面。
- 进入具体书籍后：导航切换为当前书籍上下文。
- 所有非认证页面都包裹在同一个应用外壳下。

这个心智模型足以覆盖大部分后续维护场景。
