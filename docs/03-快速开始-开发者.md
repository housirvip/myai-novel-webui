# 快速开始（开发者）

这份文档面向第一次接手这个仓库的开发者，目标是帮助你尽快把项目跑起来，并建立一个有效的阅读顺序。

## 1. 技术栈概览

当前仓库是一个前端单页应用，主要技术栈如下：

- React 19
- TypeScript 5
- Vite 6
- React Router DOM 7
- TanStack React Query 5
- Tailwind CSS 3
- Radix UI
- Vitest + Testing Library

## 2. 本地启动

### 安装依赖

```bash
npm install
```

### 启动开发服务器

```bash
npm run dev
```

默认开发服务器运行在：

- `http://127.0.0.1:5173/app/`

### 开发代理说明

开发模式下，前端会把以下请求转发到本地后端：

- `/api` → `http://127.0.0.1:3000`
- `/health` → `http://127.0.0.1:3000`

这意味着你通常需要同时准备后端服务，前端才能拿到真实数据。

## 3. 常用命令

```bash
npm run dev      # 启动开发服务器
npm run build    # 构建生产版本
npm run preview  # 预览构建结果
npm run check    # TypeScript 类型检查
npm run test     # 运行测试
npm run test:watch
```

## 4. 推荐的阅读顺序

如果你第一次进入这个仓库，建议按下面顺序阅读：

1. `src/app/App.tsx`
2. `src/app/providers.tsx`
3. `src/app/router.tsx`
4. `src/app/layouts/AppShell.tsx`
5. `src/app/auth.tsx`
6. `src/app/route-guards.tsx`
7. `src/pages/*`
8. `src/lib/api.ts`
9. `src/lib/query/query-client.ts`
10. `src/lib/query/query-keys.ts`
11. `src/lib/routes.ts`
12. `src/lib/types.ts`

这样看下来，你会先理解应用怎么启动，再理解路由、鉴权、页面、数据流和类型模型。

## 5. 目录职责

### `src/app`

放应用级能力：

- 根组件
- Provider 组合
- 路由定义
- 布局外壳
- 鉴权上下文
- 页面守卫

### `src/pages`

放页面级业务编排。每个页面通常负责：

- 调用 query / mutation
- 组织页面结构
- 处理页面级状态
- 串联导航和业务动作

### `src/components`

放可复用组件。当前代码中比较重要的是资源编辑相关组件，它们同时服务资源中心和章节工作台。

### `src/lib`

放相对底层和共享的能力：

- API 封装
- 各领域接口模块
- query key
- query client
- 路由工具
- 类型定义
- 通用工具函数

### `src/test`

放测试基础设施和共享测试工具。

## 6. 如果你要改某类问题，应该先看哪里

### 改页面展示或交互

先看对应 `src/pages/...` 文件。

### 改整体布局或导航

先看 `src/app/layouts/AppShell.tsx`。

### 改登录、注册、会话恢复

先看：

- `src/app/auth.tsx`
- `src/app/route-guards.tsx`
- `src/lib/auth-api.ts`

### 改路由或跳转路径

先看：

- `src/app/router.tsx`
- `src/lib/routes.ts`

### 改接口请求或错误处理

先看：

- `src/lib/api.ts`
- 对应的 `src/lib/*-api.ts`

### 改缓存、失效或服务端状态行为

先看：

- `src/lib/query/query-client.ts`
- `src/lib/query/query-keys.ts`
- 对应页面中的 `useQuery` / `useMutation`

### 改资源编辑能力

先看：

- `src/components/resources/ResourceEditorForm.tsx`
- `src/components/resources/resource-editor-shared.ts`
- `src/pages/resources/ResourcesPage.tsx`
- `src/pages/chapters/ChapterWorkbenchPage.tsx`

## 7. 当前项目的一些关键事实

- 路由基于 `/app/` 作为前端主基路径。
- 大部分业务页面都要求登录后访问。
- 服务端状态以 TanStack React Query 为核心。
- API 默认以 JSON 形式交互，并使用相对路径 `/api/...`。
- 用户个人运行配置会影响章节工作流的默认参数。

## 8. 推荐的接手方式

对于第一次接手的人，不建议一开始就从组件细节入手。更好的顺序是：

1. 先把系统当作“AI 小说工作流控制台”理解。
2. 从页面流转去理解产品结构。
3. 再回到代码层看路由、鉴权、数据流。
4. 最后再进入某一个页面的具体实现。

这样能更快看懂全局，也更不容易陷入局部细节。
